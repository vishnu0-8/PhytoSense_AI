# PlantAI production deployment preparation

This is a deployment-preparation copy. Your original project and local database are not modified.

## Hosting layout
- Frontend: Vercel, project root `frontend`
- Backend: Render, repository root
- Backend model: `outputs/checkpoints/best_model.pth`
- SQLite: Render persistent disk at `/var/data/detection_history.db`

## Render environment
The included `render.yaml` creates a web service and persistent disk. Set these values in Render:
- `GROQ_API_KEY`: your Groq API key (secret)
- `CORS_ORIGINS`: exact deployed Vercel origin, e.g. `https://plantai.vercel.app` (no trailing slash)
- `AUTH_SECRET_KEY`: generated by the blueprint; do not change after deployment unless intentionally invalidating sessions

`AUTH_COOKIE_SECURE=true` and `DATABASE_PATH=/var/data/detection_history.db` are configured for production.

## Vercel environment
- Root Directory: `frontend`
- Build Command: `npm run build`
- Output Directory: `dist`
- Environment Variable: `VITE_API_URL=https://YOUR-RENDER-SERVICE.onrender.com`

Redeploy frontend after setting/changing `VITE_API_URL`.

## Existing local farmer data
The local SQLite database is intentionally not included in this source deployment ZIP. Keep a separate backup of `database/detection_history.db`. Before going live with existing farmer accounts/history, copy that database to the Render persistent disk at `/var/data/detection_history.db` while the service is stopped. Do not overwrite a live production database. The database schema is preserved and the code uses the persistent path when `DATABASE_PATH` is set.

## Secrets
No `.env` files are included. Do not commit API keys, JWT secrets, database files, `.git`, or `node_modules`.

## Notes
- The old Gradio UI is not included in the runtime dependency list; the React/Vite frontend is the intended UI.
- The model checkpoint is included in the package.
- First deployment still requires configuring Render and Vercel, setting the environment variables, and verifying the hosted service. This package has not been deployed to either provider.
